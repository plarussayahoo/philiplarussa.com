NETWORK ENGINEERING • ACTIVE DEVELOPMENT

PCAP Analyzer

An evidence-driven network investigation platform that transforms packet captures into structured TCP connection analysis while preserving the packet-level evidence behind each conclusion.

Python FastAPI TShark Docker TCP/IP Packet Analysis

01 / OVERVIEW

Turning packet captures into investigations.

Packet captures contain enormous amounts of diagnostic evidence, but answering a seemingly simple question such as “what happened to this connection?” can require manually following TCP streams, flags, sequence behavior and endpoint activity.

PCAP Analyzer was created to automate that investigative process without replacing the underlying evidence.

Engineering Objective

Reduce the time required to investigate network behavior while keeping every assessment explainable from observable packet data.

02 / PROBLEM

Network failures rarely explain themselves.

01

Large Captures

A single PCAP can contain thousands of packets and many unrelated connections, making manual inspection slow.

02

Partial Behavior

Connections do not always complete a clean TCP lifecycle. SYN-only attempts, resets and incomplete handshakes require context.

03

Evidence vs. Assumption

A troubleshooting tool should distinguish what the packets demonstrate from what an analyst might infer.

05 / CAPABILITIES

Connection behavior made visible.

Handshake Detection

Identifies observable SYN and SYN-ACK behavior associated with TCP connection establishment.

Partial Handshakes

Surfaces incomplete connection attempts instead of assuming every stream represents an established session.

Reset Analysis

Identifies TCP resets and the endpoint responsible for initiating the reset when supported by the capture.

FIN Analysis

Examines graceful connection-termination behavior and participating endpoints.

Retransmissions

Surfaces retransmission evidence that can help explain connection-quality or delivery problems.

Endpoint Roles

Infers likely client/server or initiator/responder roles from observable TCP behavior.

Stream Drill-Down

Allows an investigator to move from the overall capture into the evidence associated with an individual TCP stream.

Connection Assessment

Produces structured assessments based on observed packet behavior rather than generic failure labels.

Evidence Preservation

Keeps the supporting packet observations visible so conclusions can be independently reviewed.

06 / ENGINEERING DECISIONS

Designed for explainability.

Evidence before classification.

The application records observable connection behavior before assigning a higher-level assessment.

Do not treat missing packets as facts.

Packet captures can begin late, end early or miss traffic. The analysis therefore distinguishes absence of evidence from evidence that an event did not occur.

Preserve stream-level context.

Summary views accelerate investigation, but analysts must still be able to inspect the individual stream supporting a result.

Separate endpoint identity from endpoint role.

IP addresses and ports identify endpoints; TCP behavior helps determine which endpoint initiated or responded to the connection.

08 / ENGINEERING CHALLENGES

The difficult part is interpretation.

Incomplete Captures

The absence of a handshake packet does not necessarily prove the handshake never occurred.

Connection Classification

TCP flags need to be interpreted as a sequence of events rather than isolated packet attributes.

Role Identification

Endpoint roles must be inferred from behavior rather than assuming that a particular IP or port always represents a client or server.

10 / LESSONS

What this project reinforces.

Network troubleshooting improves when observations, interpretations and conclusions are treated as separate layers.

Automation is most useful when it accelerates the analyst's reasoning without removing the ability to inspect the original technical evidence.

Core Principle

The tool should help an engineer reach the evidence faster—not ask the engineer to blindly trust the tool.
