Enterprise Dependency & Network Map

01 / THE PROBLEM

The dependency picture lives in too many places.

CMDB exports describe infrastructure. Application configuration reveals service dependencies. Kubernetes, source repositories, firewall policies and routing tables each hold another part of the picture.

This platform brings those relationships together so dependency investigation and change planning can start from a connected model.

Engineering objective

Understand what relies on a service, how traffic reaches it, and which dependencies deserve review before a change.

02 / CONNECT THE EVIDENCE

From system inventory to application relationships.

01

CMDB Dependency Mapping

Turns CMDB exports into an application and infrastructure dependency view, showing what relies on what.

02

Application Dependency Discovery

Parses application configuration across source repositories to identify databases, APIs and third-party services. Dependencies are classified as in-cluster, Azure, on-premises, internet or unresolved.

03

Kubernetes and DevOps Mapping

Connects AKS clusters, ingress and Azure DevOps repositories into a single dependency picture.

04

Firewall and Routing Correlation

Walks flows through firewall policies, live routes, user-defined routes and IPsec tunnels to flag firewall bypass, blocked traffic and missing return routes.

03 / THE WORKFLOW

Collect. Correlate. Explore.

  1. 01 / INPUTS

    Collect the evidence

    CMDB exports, application configuration, cluster information and network configuration.

  2. 02 / RELATIONSHIPS

    Build the model

    Connect applications, infrastructure, service dependencies and network paths.

  3. 03 / INVESTIGATION

    Ask better questions

    Explore an application, trace a flow, inspect dependencies or export a diagram.

04 / MAKE IT USEFUL

Investigate the relationship.

IMPACT

What breaks if this goes down?

Investigate downstream dependencies through the graph rather than reconstructing the relationship from separate configuration files.

EXPLORATION

Start broad. Drill down.

Search, inspect zone roll-ups, drill down by application, and look up rules by IP and port.

EXPORT

Take the model with you.

Export PNG diagrams, GraphML for yEd or draw.io, and CSV for further analysis.

05 / THE OPERATING MODEL

Read-only collection. Local execution.

01

Queryable Data Store

Publishes results to SQLite through a read-only API, with an optional Neo4j graph load for Bloom exploration.

02

Read-Only and Local

Works from exports and read-only queries. The platform runs locally in Docker, keeping assessment data in the local environment.

03

Refresh Detection

Detects changed inputs and re-runs only the affected pipelines.

Built with Python · Flask · Graphviz · Cytoscape.js · SQLite · Neo4j · Docker · Azure CLI / kubectl · Firewall and routing analysis
